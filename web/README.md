# rt511 web

The video wall. Vite + React 19 + TypeScript, with `hls.js` for the camera video.

React owns navigation, the breadcrumb, the region list, the wall's tile grid, the camera panel's chrome and the splitter's width. It does not own the drawing: the national map, the region map, the projection, the graph topology, the digital PTZ and the hls.js lifecycle stay imperative modules that a component builds in an effect and tears down in its cleanup. Pushing thousands of canvas paths through the virtual DOM would be strictly worse, and a video element that React re-parents is a video element that stops.

Two consequences worth knowing. First, `StrictMode` is on deliberately: it double-invokes every effect in development, which is the pressure that catches a player or an observer that is not torn down, so every imperative view has a `destroy()`. Second, the camera panel is rendered once, in one place in the tree, and placed by CSS grid rather than moved between parents — that is what keeps a single `<video>` and an uninterrupted stream across a view switch.

```
pnpm install   # from the repo root; this is a pnpm workspace
pnpm mock   # fake backend on 127.0.0.1:8511, in a second terminal (PORT to move it)
pnpm dev    # http://localhost:5173, proxies /api to 8511
pnpm build  # type-checks, then writes dist/
```

`RT511_API=http://127.0.0.1:8512 pnpm dev` points dev at a different backend, which is how the mock runs alongside a real the server that already holds 8511.

`pnpm mock` serves the same routes as the server with invented data and procedurally drawn PNG frames, so the frontend can be developed without touching any agency's cameras. It cannot synthesise video, so every camera answers as one without a stream and the hero falls back to snapshots, which is the same path a real camera without a stream takes.

Every response is shape-checked at the boundary before anything downstream sees it. `as T` on a parsed body is an assertion, not a check, and the backend is Python with no shared schema, so a renamed field would otherwise surface as an undefined in a draw call far away. The predicates in `validate.ts` check the fields the UI actually reads, including that the parallel camera arrays in `/api/national` are the same length, and a mismatch degrades exactly as an unreachable backend does: one warning naming the field path, and a null return. That check earned its keep on its first run, catching `graph.cameras[N].site: expected a string, got null` — three of today's 669 cameras cannot be placed on a road, and the old code carried that null into the map.

Coordinate order is a type, not a convention. `/api/graph` and `/api/roads` send `[lat, lon]`; `/api/national` sends GeoJSON `[lon, lat]`. Both are pairs of numbers, so a swap compiles and draws a plausible rotated map. `coords.ts` brands them apart, the branding is applied in the validation layer where each endpoint's order is read off its contract once, and a swap is now a compile error rather than a picture that looks nearly right.

The wall polls `/api/cameras` every 10 s and re-ranks tile sizes every 20 s. Tile size follows the `activity` score, not the raw frame difference: the top few cameras get a 2x2 span, the next tier 2x1, everything else 1x1, with a few ranks of hysteresis so two cameras trading places do not reflow the grid. Tiles are created from the poll state rather than from the graph, because the backend can be started on a subset (`--cameras freeway`) and blank tiles for unpolled cameras would read as breakage.

The app has three levels: the country, a region, and a camera. The country view is the landing page and draws `/api/national`: every state outline, the seventeen this install has a source for filled brighter than the rest, and all 19,327 catalogued cameras as a density layer. Individual dots say nothing at country scale, so cameras are binned into six-pixel screen cells coloured from steel blue where they are sparse to near white where they pile up; zoom in past the point where a cell is finer than the cameras are spaced and the same data draws as individual positions. The ramp deliberately stops short of amber, because amber on that map means a region is being polled right now. A live region gets a filled amber marker and one slow pulse ring, a region that is configured but not polled gets a dashed outline, and the list beside the map says plainly how many of the configured regions this run actually polls. Only a polled region can be opened, because `/api/graph` merges the regions being served and there is no geometry for the others.

The projection is an Albers USA composite: a conic equal-area for the lower 48, with Alaska and Hawaii projected in their own conics and placed as framed, labelled insets under the south-west corner. That is the traditional answer and it is the right one here — in a single conic, Alaska either swallows the map in empty ocean or smears across the top, and this view exists to show where cameras are rather than to be a reference atlas. Note that `/api/national` gives polygon coordinates as `[lon, lat]` while `/api/graph` and `/api/roads` give `[lat, lon]`.

The region map view (`M`, or the button in the top bar) draws the region's roads and the camera graph on one canvas, with the selected camera docked beside it. Roads come from `/api/roads?region=<key>`, one region at a time because all of them together is about 2.5 MB, and each class is built once into a `Path2D` in world coordinates and restroked on every frame, so a pan costs eleven strokes rather than thousands of path rebuilds. Canvas rather than SVG: a region is six to nine thousand ways and one node per way makes panning crawl. There are no tiles and no external requests of any kind, which is the same reason the standalone map draws roads as vectors. Site dots carry the live state, growing and warming towards amber with `activity` and staying dim while a camera has no frames. Only sites whose cameras the backend is actually polling are click targets: the graph describes 312 cameras and a poller started on a subset serves frames, streams and snapshots for exactly those, 404 for the rest.

Site dots and edges carry the graph itself. Edges are coloured by kind the way the standalone `out/graph_<region>.html` map does it, blue freeway, green street, amber ramp and dashed violet sister, over a dim blue-slate road background that stays context rather than competition, and a node is ringed in the colour of what it sits on with a halo in the background colour so it lifts off the line underneath. Selecting a node restrokes its own edges over the bulk paths and steps the rest back slightly. Activity drives a node's size and warms it towards amber past 0.6, which is the same threshold the wall uses for a hot tile; below that a node keeps its kind's colour, because interpolating blue to amber across the whole range runs through grey and made a middling camera look dead.

The camera never crops. The stage takes the shape of whatever is playing, which varies across agencies from about 320 pixels wide to 1280, and fits the frame inside it, so nothing is thrown away; docked beside the map it fills the column's height instead, and the splitter between map and camera sets how much room that is. The splitter is a real control: drag it, focus it and use the arrows, double-click to reset, and the width is remembered in localStorage. `F` expands the camera to the whole viewport, the Fullscreen button hands the same element to the browser's fullscreen, and `Escape` steps out of expanded before it closes the camera.

The camera image has digital pan, tilt and zoom, which is all that is possible against a public read-only feed. Scroll to zoom, drag to pan, double-click to reset. The transform sits on a wrapper holding both the video and the replay still, so it applies to either, and it is clamped so the picture can never be panned off its own edge and reset whenever the camera changes. Past 2.2x the source pixels are rendered `pixelated` rather than smoothed, because some agencies publish frames about 320 pixels wide and an upscale blur at that size looks worse than honest blocks.

Keys: `Space` toggles the corridor tour, `M` switches between wall and region map (and at the country level steps down into the first polled region), `F` expands the camera, `Escape` steps up one level at a time, out of expanded, then out of the camera, then out of the region, and arrows step along graph edges (right and down are downstream). The breadcrumb in the top bar does the same with the mouse.

The fragment tracks the level and is read once at load, so a screen can be pointed at any of them: `#view=national`, `#view=map&region=des-moines-ia`, `#view=wall&region=oakland-ca`, `#cam=17961432`, `#tour`. Naming a camera or a region without a view implies the region level.
